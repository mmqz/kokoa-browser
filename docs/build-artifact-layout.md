# 构建产物的存放约定（2026-09-16 整理）

> 起因：E:\ 下散落了 k4、k5 等一堆目录，E:\temp 里堆了 20+ 个
> 10MB 级的构建日志，还有解压残留。磁盘虽然不紧张（还剩 500+ GB），
> 但**散落的东西迟早会被误删或混淆**。

---

# 一、目录约定

```
E:\builds\                          <- 【唯一】放构建产物的地方
  <run-id>\                           例：35032271818
    kokoa-0.1.0t.en-US.win64.zip      下载的原始产物（保留，供复查）
    omni.ja                           解出来的（核对用，核对完可删）

E:\temp\                            <- 临时文件（可随时清空）
```

**说明**：
- 用 **run-id 作目录名** —— 它唯一对应一次构建，不会混淆。
- 不再用 `k4` / `k5` 这种序号（过几天就想不起来哪个是哪个）。
- 同一次构建里，`omni.ja` 从 zip 里解出来核对，
  **核对完就删**（它 107MB，是 zip 里的重复内容）。

# 二、什么时候删

| 东西 | 什么时候删 |
|---|---|
| 旧 run 的整个目录 | **新构建验证通过后** —— 一次只留【最近一个成功的】 |
| `omni.ja`（解出来的） | 核对完立刻删 |
| 构建日志（b*.txt） | 定位完问题就删；**不要留一堆** |
| 解压残留（tmpaddon*） | 立刻删 |
| `E:\temp` 整体 | 可随时清空，不存有价值的东西 |

# 四、核对产物的正确姿势（**必读**）

**核对前先确认改动在那次构建里**，否则是"拿旧产物找新代码"：

```bash
sha=$(gh api repos/<owner>/<repo>/actions/runs/<id> --jq '.head_sha')
git merge-base --is-ancestor <commit> $sha   # 0 = 在构建里
```

详见 `docs/artifact-verification.md`。

# 五、一个提醒

**`engine/` 源码树没有下载到本地**（几百 MB ~ GB 级），
所以本地**不能**直接对比"我们的 src 与构建实际用的源码"。
要确认某个改动进没进产物，**只能下载产物核对**。
