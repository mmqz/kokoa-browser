# 二、正确的核对流程

```bash
# 1. 拿到构建用的提交
gh api repos/<owner>/<repo>/actions/runs/<id> --jq '.head_sha'

# 2. 对每个「我想验证的改动」，确认它是 headSha 的祖先
git merge-base --is-ancestor <commit> <headSha>
echo $?   # 0 = 在构建里；非 0 = 不在

# 3. 只核对【确认在构建里】的那些改动
```

**否则就是对着一份旧产物找新代码。**

---

# 三、一个更简单的判据：提交时间 vs 构建触发时间

```bash
git log -1 --format='%ci' <commit>          # 提交时间
gh api .../runs/<id> --jq '.run_started_at'  # 构建开始时间（UTC！）
```

**注意**：GitHub 的时间是 **UTC**，本机 `git log` 是**本地时区**。
不能直接相减 —— 我就为此误判过一次（把 75 分钟看成 9 小时）。

# 五、顺带确认的两个「虚惊」

## 5.1 字节数差异不是问题
```
产物 ZenWelcome.mjs: 28113 字节
我们源文件:          29059 字节
差 946 字节 = 891 行 × 1 字节
```
**那是 CRLF vs LF**（git 在 Windows 上会自动转换）。
不是内容差异 —— 别被字节数骗了。

## 5.2 「skipRoute 丢了」也是虚惊
```
我在 zen-sets.js 里搜不到 skipRoute，一度以为重构时丢了。
实际：它被【正确地搬到了】 KokoaAiPanel.mjs 的 openAiTab 里
      （那是更合理的位置 —— 因为「开标签」这个动作在那里）。
```
**搜不到 ≠ 丢了。** 先确认它是不是搬到了别处。
